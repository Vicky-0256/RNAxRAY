# External evidence (RNAcentral MCP), first version — contract

Design: `../../RNACENTRAL_MCP_TASK.md` is the task book; this file is the
interface the Go shell and the Python evidence worker share. Status:
implemented in desktop/app/core/evidence.go and desktop/runtime/evidence/.

RNAxRay is an MCP **client host**. A separate Python process (the *evidence
worker*) speaks RNAxRay's newline JSON to Go and the official MCP Python SDK
(v1, pinned) to one fixed RNAcentral MCP server child over stdio. The control
and compute sidecars never wait on the network.

## Verified upstream behaviour (2026-10-15, rnacentral-mcp-server 0.1.1, mcp 1.30.0)

- `initialize` → serverInfo `RNAcentral MCP Server` with **the SDK version**
  (1.30.0), not the package version: read the package version with
  `importlib.metadata.version("rnacentral-mcp-server")`.
- tools: get_secondary_structure_svg, map_rna_id, query_rnacentral,
  export_sequences, get_overlapping_ncrnas, get_rna_description,
  search_sequence. Only **get_rna_description** and **map_rna_id** are allowed
  in v1.
- `isError` is false for every outcome. get_rna_description returns:
  - a summary starting `WARNING: This summary was generated by AI.` with
    `[PMC…]` markers (mmu-mir-191, hsa-mir-21);
  - `Error querying RNAcentral API: 404, message='Not Found', url=…` for an
    unknown id **and** for an id without a summary (indistinguishable, e.g.
    `KX377335`, `not-a-real-rna-xyz`);
  - `No description available` (code path; not observed yet);
  - `Error querying RNAcentral API: …` for network errors.
- map_rna_id answers plain text, e.g. `No RNAcentral entry found for external
  ID: hsa-mir-21` (names are not external ids; mapping is advisory only).
- What leaves the machine (source of 0.1.1 plus an observation): both allowed
  tools only issue `GET https://rnacentral.org/api/v1/...` with no body —
  get_rna_description `litsumm/<rna_id>`, map_rna_id `rna/?external_id=<id>`,
  `rna/<urs>/xrefs[/<taxon>/]`. During the live test (`TestEvidenceLive`,
  2026-10-15) `lsof` sampled every 0.1 s showed the evidence processes'
  only sockets as TCP to 193.62.193.83:443 (rnacentral.org, EBI); nothing
  else was contacted.
- Taxon changes identity (live, worker directly): map_rna_id
  `MIMAT0000076` + 9606 → `URS000039ED8D_9606` (hsa-miR-21-5p), + 10090 →
  `URS000039ED8D_10090` (mmu-miR-21a-5p), both success; `URS000075E9E1` +
  9606 → "No cross-references found…" (`not_found_or_no_summary`). This is
  why Go only sends `describe` after the user confirmed id and taxon.

- Summaries are keyed by the miRBase precursor name (live, 2026-10-15):
  `hsa-mir-21` has a summary, while `URS000039ED8D_9606`,
  `URS000039ED8D_10090`, `URS000039ED8D` and the mapping's canonical
  `hsa-miR-21-5p` all answer 404; map_rna_id maps external ids
  (`MIMAT0000076`, `NR_029493` → `URS000039ED8D_9606`) but not names. So a
  summary cannot be reached through a species-checked mapping, and the
  taxon never travels with get_rna_description. Go checks it by the name
  instead: for a miRBase name with a known prefix (`hsa` 9606, `mmu` 10090,
  `aae` 7159, … in `core/evidence_taxon.go`) a contradicting taxon is
  refused before any request, and the card records `taxon_check:
  name_prefix` (an empty taxon becomes the prefix's); any other identifier
  records `taxon_check: not_checked` and is shown as "as entered; not sent
  to RNAcentral, not checked".

## Worker protocol (Go ↔ Python)

`python -m desktop.runtime.evidence.worker --serve`, stdin
`{"id":N,"request":{...}}`, stdout `{"id":N,"response":{...}}` (contract C1,
same framing as the bridge). Environment: only `PYTHONDONTWRITEBYTECODE=1`,
`PYTHONUNBUFFERED=1`, `PYTHONIOENCODING=utf-8`, `RNAXRAY_EVIDENCE_CACHE=<dir>`,
`RNAXRAY_EVIDENCE_LOG=<dir>` (redacted log); no project paths, no credentials.
The worker starts the MCP server child lazily and keeps one session.

Operations (anything else → `{"ok":false,"error":"unsupported evidence operation"}`):

| operation | request | response |
|---|---|---|
| `status` | `{}` | `{ok, connected, server_package_version, sdk_version, adapter_version, tools:[…allowed tools found…]}`; `connect:true` starts the server and lists tools (connection test) |
| `describe` | `{rna_id, taxon?, force?}` | `{ok:true, card: EvidenceCard}` (cached by provider/tool/rna_id/taxon/versions unless `force`) |
| `map_id` | `{identifier, taxon}` | `{ok:true, card: EvidenceCard}` with `content_kind: database_metadata` |
| `shutdown` | `{}` | closes the MCP session and child, then exits |

Timeouts: Go cancels by killing the worker's process group after 45 s per
call. The MCP SDK starts the RNAcentral child in its own session, so the
group kill does not reach it: the child ends on EOF of its stdin when the
worker dies (checked: it exits about 0.1 s later). The worker keeps one
request, retry included, within 40 s (`REQUEST_BUDGET`, so before Go's 45 s):
starting the server (at most 30 s) and the tool call (at most 30 s) only get
the time left, and the single retry for a lost server (never for 404) starts
only with 10 s left. Rate limit: at most 2 calls per second.

## EvidenceCard (JSON; worker produces, Go stores)

```json
{
  "schema_version": "1.0",
  "evidence_id": "ev-<uuid4 hex>",
  "source_provider": "RNAcentral",
  "source_tool": "get_rna_description",
  "adapter_version": "rnaxray-evidence 1.0",
  "server_package_version": "0.1.1",
  "sdk_version": "1.30.0",
  "query_identifier": "hsa-mir-21",
  "taxon": "9606" | null,
  "identity_confirmation": "user_confirmed" | "unconfirmed",
  "requested_at": "2026-10-15T08:00:00Z",
  "retrieved_at": "2026-10-15T08:00:01Z" | null,
  "status": "success" | "summary_unavailable" | "not_found_or_no_summary" | "upstream_error" | "local_error" | "timeout" | "cancelled" | "identity_unconfirmed" | "unexpected_response",
  "status_detail": "HTTP 404 Not Found" | null,
  "content_kind": "external_ai_summary" | "database_metadata",
  "display_text": "...",           // null unless success (or mapping text)
  "raw_response_digest": "sha256:<hex of the raw tool text>",
  "raw_response_local_ref": null,  // set by Go on attach (evidence/<id>.raw.txt)
  "source_identifiers": ["PMC5549916", ...],   // only ids present in the text
  "citation_verification": "not_checked",
  "relation_to_current_structure": "background_only",
  "review": {"state": "unreviewed", "reviewer": null, "at": null},
  "source_url": "https://rnacentral.org/..." | null,
  "binding": null                  // set by Go when attached: see below
}
```

Classification order (worker): local timeout / cancel / protocol error →
MCP `isError` → known texts of the pinned version (`Error querying RNAcentral
API: 404` → `not_found_or_no_summary`; other `Error querying RNAcentral API:` →
`upstream_error`; `No description available` → `summary_unavailable`) → empty
or non-text → `unexpected_response` → otherwise `success` with
`content_kind: external_ai_summary`. A 404 is never reported as "no
summary", and nothing is ever reported as "not studied".

`identity_unconfirmed`: Go refuses `describe` unless the user confirmed the
identifier and taxon in the UI (`identity_confirmation: user_confirmed` is
sent by Go); the worker never decides identity.

## Storage and binding (Go)

- Cards attached to a project: `<project>/evidence/<evidence_id>.json` plus
  `<evidence_id>.raw.txt` (raw tool text). Never in project.json's analysis
  fields; listed by reading the directory. Only public query fields leave the
  machine; project ids, paths and structure data never reach the worker.
- `binding` (local only): `{project_id, structure_id, record, result_digest,
  attached_at, include_in_report}`; `result_digest` = sha256 of the bound
  structure's dot-bracket. A card bound to another structure/record is shown
  as "for another result" and never carried over.
- Card files travel with the project, so their content is only as
  trustworthy as whoever wrote them last. Go writes `local_seal`
  (`hmac-sha256:<hex>` of the card JSON without it) under a 32-byte key kept
  beside the preferences (`evidence-seal.key`, 0600, not in the cache), when
  it attaches a card and when it updates a card whose seal checks out. A card
  without a valid seal (made on another computer, or edited since) is shown
  and reported as "made or edited on another computer: its text and review
  are not verified here"; updating it does not seal it. Read back, every card
  has `citation_verification: not_checked` and
  `relation_to_current_structure: background_only`, whatever the file says.
- The cache (`RNAXRAY_EVIDENCE_CACHE`, app cache dir) keeps raw responses by
  `(provider, tool, query_identifier, taxon, server_package_version,
  adapter_version)`, 7 days; Preferences can clear it.
- Preferences: `external_lookup` (bool, default **false**). With it off, Go
  refuses every evidence call before starting the worker.
- Go implementation notes (clarifications, 2026-10-15):
  - `describe` / `map_id` responses may carry `raw_text` (the raw tool
    text) next to `card`; Go keeps it only when its sha256 equals
    `raw_response_digest` and writes it to `<project>/evidence/<id>.raw.txt`
    on attach (`raw_response_local_ref: "evidence/<id>.raw.txt"`).
  - Gated on `external_lookup`: status, describe, map_id and attaching a
    card. Listing, updating, deleting saved cards, clearing the cache and
    cancelling stay available with it off (local only).
  - Go resets `review`, `citation_verification`, `binding` and
    `raw_response_local_ref` on every worker card. Review states:
    `unreviewed`, `reviewed`, `rejected`, set only by the user; `review.note`
    (optional) is the researcher's note shown in the report.
  - Only `success`, `summary_unavailable` and `not_found_or_no_summary`
    cards can be attached. `source_url` is kept only when it starts with
    `https://rnacentral.org/`.
- Python worker notes (clarifications, 2026-10-15):
  - Responses carry `raw_text` and `cached: bool` next to `card`.
  - `raw_response_digest` and `retrieved_at` are null when no tool response
    arrived (timeout, lost connection); non-text content hashes as "".
  - Lost transport / server failed to start → `local_error` (the MCP server
    is a process on this computer; RNAcentral's own errors arrive as tool
    text and stay `upstream_error`); MCP protocol
    errors, refused or unlisted tools, responses over 256 KiB →
    `unexpected_response`; MCP `isError` → `upstream_error`. The worker never
    emits `cancelled` or `identity_unconfirmed` (Go does).
  - map_id: "# ID Mapping for" → success; "No RNAcentral entry found…",
    "No cross-references found…", "Could not determine a valid Taxon ID…" →
    `not_found_or_no_summary`; "Error looking up external ID…" →
    `upstream_error`; other text → `unexpected_response`. A returned taxon
    other than the requested one stays success with a status_detail; the
    worker never decides identity.
  - Request fields are strict (unknown fields → ok:false, nothing sent).
    Identifiers `[A-Za-z0-9_.:|-]{1,100}`; taxon `[0-9]{1,10}` or
    `[A-Za-z .-]{1,64}`.
  - The SDK starts the MCP child in its own session; it exits when the
    worker's pipe closes (checked with SIGKILL of the worker mid-call).
  - No clear_cache operation: Go deletes the cache directory. The server's
    stderr logs the queried ids, so it is discarded (and an
    `rnacentral-server.log` left by an earlier version is deleted when the
    worker starts); `RNAXRAY_EVIDENCE_SERVER_LOG=1` keeps it for debugging, one
    session per file, never appended.
  - The lock (`desktop/runtime/requirements-evidence.txt`, 46 pins, 65
    hashes) covers macOS arm64, Windows amd64 and Linux x86_64; on Linux the
    cryptography wheel pip selects needs glibc ≥ 2.34.
- Report: section "External sources and researcher notes", only cards with
  `include_in_report`, showing provider, tool, query, retrieval date, status,
  "External AI literature summary — not a validation of this structure",
  review state, and "citations not verified" when `citation_verification`
  is not `verified`. No numbers or methods of RNAxRay results are changed.
